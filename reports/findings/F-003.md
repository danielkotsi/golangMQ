# F-003: Broker never replies `channel.close-ok` — `ClientChannel.Close()` always times out

Status: **RESOLVED** — broker now replies `channel.close-ok`; the close
handshake completes on the response path.

## Finding

When a client closes a channel, the broker processes the teardown but never
acknowledges it. The client therefore has to rely on its own client-side
timeout to be unblocked; a protocol-correct `channel.close-ok` round trip never
completes.

## Observed behaviour

`TestChannel_CloseRequeuesUnacked` exercises `ClientChannel.Close()`:

```go
ctx, cancel := context.WithTimeout(context.Background(), 700*time.Millisecond)
_ = ch.Close(ctx) // always returns ctx.Err(); requeue is asserted anyway
```

The close *works* on the broker side — the channel is deleted from the
connection and its consumers are unregistered — but `Close` never resolves via
the response channel; it only returns when the context deadline fires.

These observations hold:

- The requeue/cleanup side works: unacked delivery bodies are re-enqueued and
  observable by another consumer (`channel.close` → `Channel.cleanup` →
  `queue.unregisterConsumer` requeues `pendingMessages`).
- The acknowledgement side never works: the SDK's `handleChannelCloseOK` is
  registered in the read loop but no `channel.close-ok` envelope ever arrives,
  so `ClientChannel.Close(ctx)` always returns `ctx.Err()`.
- A channel closed this way also never locally closes its `Incoming` delivery
  channel on the SDK side (that is done only on receipt of close-ok), so the
  caller cannot rely on `Incoming` closing to detect the close.

## Why that behaviour

`Connection.ChannelClose` (broker/connection.go) performed the teardown
but never wrote an acknowledgment envelope:

```go
func (c *Connection) ChannelClose(env protocol.Envelope) {
	id := env.ChannelID
	c.mu.Lock()
	ch, ok := c.channels[id]
	delete(c.channels, id)
	c.mu.Unlock()
	if ok {
		ch.cleanup()
	}
	// <- missing: c.WriteEnvelope(id, ChannelCloseOKType, env.RequestID,
	//    protocol.ChannelCloseOK{ID: id})
}
```

Contrast `ChannelOpen` (connection.go:241-259), which does reply
`channel.open-ok`.

The SDK side already implements the full handshake:
`ClientChannel.Close` (channels.go:84-102) sends `channel.close` and waits on
the registered response channel; `Client.handleChannelCloseOK`
(client.go:364-383) resolves it, deletes the channel from the client map and
closes `Incoming`. Everything needed on the client is present; only the broker
response is missing.

## Why it needs to change

1. **Correctness of the protocol.** A request/response method (`channel.close`)
   that never gets its response is a protocol violation. The client is forced
   into a hardware/cancellation path (`ctx.Done()`) instead of the intended
   response path for every single channel close.
2. **Hidden local-state leak.** Because `handleChannelCloseOK` is what removes
   the channel from the client's `channels` map and closes the channel's
   `Incoming`, never receiving it leaves stale channel entries and an open
   `Incoming` channel client-side until the client itself is closed.
3. **Orphaned pending requests.** The SDK partially mitigates this by
   `unRegisterREQ` on `ctx.Done()`, but that is a workaround for the missing
   server reply, not a fix.

## How it needs to be countered

Have the broker reply with `channel.close-ok` in `Connection.ChannelClose`,
mirroring the `channel.open-ok` response in `ChannelOpen`:

```go
func (c *Connection) ChannelClose(env protocol.Envelope) {
	id := env.ChannelID
	c.mu.Lock()
	ch, ok := c.channels[id]
	delete(c.channels, id)
	c.mu.Unlock()
	if ok {
		ch.cleanup()
	}
	c.WriteEnvelope(id, protocol.ChannelCloseOKType, env.RequestID, protocol.ChannelCloseOK{ID: id})
}
```

Send the close-ok **after** cleanup so the client's `handleChannelCloseOK`
runs once teardown is linearised; order relative to the delete does not matter
for correctness since cleanup is channel-internal.

This is now implemented in `Connection.ChannelClose` (the missing
`WriteEnvelope` call after `ch.cleanup()`), plus the `protocol.ChannelCloseOK`
struct added to `protocol/events.go`. No SDK change was needed.
